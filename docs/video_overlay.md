# 모드 2·3과 저장 영상 오버레이

## 실행 모드

- 모드 2: 실시간 카메라 측정. 소켓은 수치·반복 이벤트만 전송합니다.
- 모드 3: `video_path`를 지정하는 오프라인 영상 분석.
- 모드 1/VISUAL은 제거했습니다. 두 경우 모두 `output_mode`는 LIGHTWEIGHT를 사용합니다.
- CALIBRATION/MAIN/TEST는 측정 목적을 구분하는 별도 설정이며 그대로 유지합니다.

소켓 세션은 영상을 항상 저장합니다. `record_video`를 생략하거나 false로 보내도 실제 저장은 true입니다.
실시간 이미지나 스켈레톤은 소켓으로 보내지 않고, CSV·NPZ·MP4로 기록합니다.

## Streamlit에서 실행

1. `python network/socket_server.py`와 `streamlit run app.py`를 실행합니다.
2. 측정 중이라면 먼저 세션을 종료해 로그를 확정합니다.
3. 화면 하단 **저장 영상 일괄 오버레이**에서 영상 폴더를 확인합니다. 기본값은 프로젝트의 `data`입니다.
4. **data 영상 전체 오버레이 생성**을 누릅니다.
5. 영상 수·현재 파일·프레임 진행률과 영상별 결과를 확인합니다.

작업은 백그라운드에서 진행됩니다. 필요하면 **오버레이 작업 중지**를 누르세요.
오버레이 작업 중에는 새 측정 세션 시작 버튼이 잠깁니다.
현재 일괄 작업은 Streamlit과 소켓 서버가 같은 PC 또는 같은 파일 경로를 공유하는 환경을 전제로 합니다.

## 분석 로그 사용

영상과 같은 이름의 CSV/NPZ를 우선 사용합니다.

```text
session1_round1_set1.mp4
session1_round1_set1.csv
session1_round1_set1.npz
```

CSV의 `video_frame_idx`로 영상과 측정값을 맞추고, NPZ의 관절 좌표로 스켈레톤을 그립니다.
NPZ가 없으면 바와 측정값만 표시합니다. 프레임 대응 정보가 없는 CSV는 재분석 대상으로 처리합니다.
원래 분석이 영상보다 먼저 끝났다면 이후 구간에는 ANALYSIS ENDED를 표시하고 새 측정값을 만들어내지 않습니다.

로그가 없으면 **로그 없는 영상도 소켓 서버에서 분석** 옵션에 따라 처리합니다.
기본값은 켜짐이며 소켓 서버가 필요합니다. 폴더/파일명에서 운동을 찾아 TEST 모드로 전체 영상을 분석합니다.
이 경우 개인 캘리브레이션 프로필을 재사용하지 않는 격리된 실험 ID와 기본 ROM을 사용합니다.
서버가 복사 녹화한 영상과 분석 로그는 해당 작업의 `analysis` 폴더에 저장합니다.
운동을 식별할 수 없으면 SKIPPED로 표시합니다. 옵션을 끄면 기존 로그가 있는 영상만 처리합니다.

식별 이름은 biceps_curl, shoulder_press, clamshell, slr, hip_knee_flexion, knee_extension입니다.
leg_raise는 hip_knee_flexion, leg_extension은 knee_extension으로 연결합니다.

## 표시 내용

- 운동 이름, 캘리브레이션 단계, 검출 누락 여부
- 좌우 ROM 가로 바와 비율, 현재 측정값
- 좌우 실제 반복 횟수, 품질, 서버 기본 배점 누적값
- 카운트 발생 시 COUNT +1 강조
- NPZ가 있으면 저장된 원본 관절 좌표 스켈레톤

스켈레톤은 NPZ의 원본 추론 좌표이며 실시간 필터 결과를 그대로 저장한 것은 아닙니다.
막대와 횟수·판정은 CSV에 실제 기록된 결과를 사용합니다.
클라이언트의 사용자 지정 배점과 서버 기본 점수는 다를 수 있습니다.

## 결과 위치

```text
data/_overlays/<작업 시각>/
├─ results.csv
├─ videos/<원본 상대 폴더>/<원본 파일명>.overlay.mp4
└─ analysis/  # 로그 없는 영상을 서버에서 분석한 경우
```

원본 영상과 로그는 덮어쓰지 않습니다. 결과 영상은 재생 시간을 유지하며 최대 1280×1280 안에서
종횡비를 유지합니다. OpenCV MP4 출력이므로 원본 오디오는 복사하지 않습니다.
`_overlays` 아래의 영상과 이미 오버레이된 파일은 다음 작업에서 제외합니다.
파일 목록은 작업 시작 시 한 번만 확정하므로 작업 도중 생성된 영상이 다시 처리되지 않습니다.

`results.csv`의 status는 COMPLETED / SKIPPED / ERROR / CANCELLED이며,
analysis는 SAVED_LOG 또는 SERVER_DEFAULT_ROM입니다. 오류나 건너뜀의 이유도 함께 기록합니다.
전체 작업이 끝나도 일부 영상이 실패할 수 있으므로 결과표를 확인하세요.
