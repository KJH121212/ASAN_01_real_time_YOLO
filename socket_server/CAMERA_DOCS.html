ASAN 실시간 카메라 캡처 시스템 상세 문서

socket_server/network/camera.py, socket_server/network/socket_server.py, streamlit_client/client/video_window.py에 구현된 통합 카메라 수신·회전·미리보기 파이프라인의 구조와 동작 원리를 정리한 기술 문서입니다.

Android USB (scrcpy 초저지연) 가속도 센서 자동 가로/세로 회전 GoPro FFmpeg DirectShow / UDP HTTP MJPEG / RTSP / Webcam 동적 비율 OpenCV 미리보기 창

1. 개요 및 전체 파이프라인

ASAN Motion 서버는 하나의 통합 클래스(ThreadedWebcam)를 통해 Android USB(scrcpy), GoPro USB(DirectShow / UDP), 모바일 IP(HTTP/RTSP), 일반 웹캠을 동일한 인터페이스로 수신합니다. 별도 백그라운드 스레드가 최신 프레임만 버퍼에 유지하므로 AI 추론(YOLO + RTMPose)과 미리보기 전송이 카메라 I/O 지연에 묶이지 않습니다.

socket_server/network/camera.py

모든 카메라 드라이버 래퍼(ScrcpyUsbCapture, FFmpegDShowCapture, ThreadedWebcam), 바이너리 탐색, 진단(scan_available_cameras) 담당.

socket_server/network/socket_server.py

카메라 연결 유지/해제, 세션 시작·종료 시 방향 잠금, 미리보기 JPEG 인코딩(encode_preview), WebSocket 명령 처리.

streamlit_client/client/video_window.py

수신된 JPEG를 독립 OpenCV 창에 표시하고, 프레임 방향 전환 시 창 크기와 비율을 자동 조정.

streamlit_client/app.py

카메라 번호·해상도 프리셋·URL(scrcpy://usb 등) 입력, 🔍 카메라 진단 및 🔌 카메라 연결 끊기 UI 제공.

2. 카메라 연결 우선순위 (ThreadedWebcam.__init__)

클라이언트가 보낸 camera_url과 camera_index를 기준으로 아래 순서대로 연결을 시도합니다. 앞 단계에서 유효한 3채널 BGR 프레임이 수신되면 즉시 연결을 확정합니다.

0차 시도
camera_url 명시 입력 시 (최우선)

• scrcpy://usb (후면), scrcpy://front (전면), scrcpy://id=<번호> → open_scrcpy_usb_camera() 직접 호출.
• http://..., rtsp://... → OpenCV CAP_FFMPEG로 IP 카메라 스트림 연결.
• URL을 명시했는데 열리지 않으면 폴백하지 않고 즉시 명확한 에러 메시지를 반환합니다.

1차 시도
사용자 지정 camera_index 또는 GoPro DirectShow

DirectShow 장치 목록(list_dshow_video_devices())에서 지정 번호 또는 GoPro 장치를 찾습니다. GoPro는 FFmpegDShowCapture(1080p 풀화각 수신 후 스케일), 일반 카메라는 cv2.VideoCapture(idx, CAP_DSHOW)로 연결합니다.

2차 시도
GoPro USB UDP 직접 스트림

172.2X.X.51 대역에서 GoPro USB 이더넷이 감지되면 HTTP API(/gp/gpWebcam/START)로 스트림을 켠 뒤 udp://@0.0.0.0:8554를 CAP_FFMPEG로 수신합니다.

2.5차 시도
USB 연결된 Android 기기 자동 감지 (scrcpy)

camera_url이 비어 있더라도 승인된 Android USB 기기(adb devices에서 state == "device")가 연결되어 있으면 자동으로 ScrcpyUsbCapture(후면 카메라, 30fps)에 연결합니다.

3차 시도
일반 활성 웹캠 폴백

가상 더미 카메라(omen cam, obs virtual, xsplit, manycam, snap camera)를 제외한 나머지 DirectShow 영상 장치 중 정상 프레임을 주는 첫 번째 카메라에 연결합니다.

3. Android USB (ScrcpyUsbCapture) 초저지연 스트리밍

별도 스마트폰 앱 설치나 가상 웹캠 드라이버 없이 scrcpy-server와 FFmpeg만으로 안드로이드 카메라의 순수 H.264 스트림을 PC 메모리(np.ndarray)로 직접 받아오는 파이프라인입니다.

3.1 연결 시퀀스

  1. adb -s <serial> push scrcpy-server /data/local/tmp/scrcpy-server.jar 로 서버 바이너리를 폰에 전송합니다.
  2. adb -s <serial> forward tcp:27183 localabstract:scrcpy 로 USB 로컬 TCP 터널을 엽니다.
  3. adb shell app_process / com.genymobile.scrcpy.Server <ver> ... 로 폰 카메라 인코더를 실행합니다.
  4. PC에서 127.0.0.1:27183 TCP 소켓(TCP_NODELAY=1)에 연결해 H.264 바이트 스트림을 ffmpeg의 stdin(pipe:0)으로 즉시 밀어 넣습니다.
  5. ffmpeg가 rawvideo / bgr24로 디코딩해 stdout으로 출력하면 _reader_loop()가 width × height × 3 바이트 단위로 읽어 NumPy 프레임으로 변환합니다.

3.2 초저지연 핵심 파라미터

구간 옵션 역할
scrcpy-server video_source=camera
camera_facing=back|front		 화면 미러링이 아닌 안드로이드 카메라 센서 직접 캡처 (Android 12+ 지원).
scrcpy-server video_bit_rate=2000000
i-frame-interval=1,max-bframes=0,priority=0		 B-frame 제거로 인코더 버퍼링 지연 제거, 2Mbps 대역폭으로 USB 전송 안정화.
scrcpy-server tunnel_forward=true raw_stream=true
audio=false control=false		 오디오/제어 채널을 끄고 헤더 없는 순수 H.264 바이트 스트림만 전송.
FFmpeg -fflags nobuffer+discardcorrupt
-flags low_delay -flags2 fast -max_delay 0		 디코더 내부 버퍼링 최소화 및 손상 패킷 즉시 폐기.
FFmpeg -probesize 32768 -analyzeduration 0 -threads 1 초기 스트림 분석 대기 시간 제거 및 싱글 스레드 저지연 디코딩.

3.3 URL 지정 형식

camera_url 값 동작
scrcpy://usb 또는 scrcpy://back연결된 Android USB 기기의 후면 카메라 사용
scrcpy://front연결된 Android USB 기기의 전면 카메라 사용
scrcpy://id=0 (예: 0, 1, 2)특정 카메라 렌즈 ID 지정 (초광각/망원 등 — scrcpy --list-cameras로 ID 조회)
안전한 리소스 정리 (release()): 연결 해제 시 TCP 소켓 종료 → ffmpeg 및 adb shell 프로세스 종료 → adb forward --remove tcp:27183 순서로 정리하므로 재연결 시 포트 충돌이 발생하지 않습니다.

4. 실시간 자동 회전 감지 & 세션 방향 잠금

Android 카메라 센서는 물리적으로 가로(1280×720) 방향으로 고정되어 있어, 폰을 세로로 세워도 원본 H.264 스트림은 가로로 들어옵니다. ScrcpyUsbCapture는 스트림을 끊지 않고 가속도 센서 폴링 + OpenCV 회전으로 이를 실시간 보정합니다.

4.1 가속도 센서 파싱 및 히스테리시스

  • _orientation_loop() 스레드가 0.6초 주기로 adb shell dumpsys sensorservice를 조회합니다.
  • Linear Acceleration 및 Uncalibrated 섹션은 건너뛰고, 실제 중력 가속도가 포함된 Accelerometer: last N events 블록의 가장 마지막(최신) 이벤트 (ax, ay, az)를 읽습니다.
  • 폰의 '자동 회전 잠금' 설정과 무관하게 물리적 기울기를 감지합니다.
  • 히스테리시스(떨림 방지): max(|ax|, |ay|) < 5.0 (책상 위에 평평하게 놓인 상태)이거나 우세 축이 반대 축의 1.35배 미만이면 직전 회전 각도를 그대로 유지합니다.
폰 물리 자세 가속도 센서 조건 후면 카메라 회전 전면 카메라 회전 결과 해상도 (720p 기준)
세로 정방향 (똑바로 세움) ay ≥ +5.0, |ay| ≥ 1.35|ax| 90° (ROTATE_90_CLOCKWISE) 270° (ROTATE_90_CCW) 720 × 1280
세로 역방향 (거꾸로 세움) ay ≤ -5.0, |ay| ≥ 1.35|ax| 270° (ROTATE_90_CCW) 90° (ROTATE_90_CLOCKWISE) 720 × 1280
가로 좌측 (상단이 왼쪽) ax ≥ +5.0, |ax| ≥ 1.35|ay| 0° (원본 유지) 0° (원본 유지) 1280 × 720
가로 우측 (상단이 오른쪽) ax ≤ -5.0, |ax| ≥ 1.35|ay| 180° (ROTATE_180) 180° (ROTATE_180) 1280 × 720
수평 놓임 / 애매한 각도 max(|ax|, |ay|) < 5.0 직전 회전 각도 유지 (화면 흔들림/플립 방지)

4.2 측정 중 방향 잠금 (set_orientation_lock)

왜 세션 중에는 방향을 잠글까?
MP4 녹화(cv2.VideoWriter)는 첫 프레임 해상도로 고정되므로, 측정 도중 1280×720 ↔ 720×1280으로 해상도가 바뀌면 프레임 기록이 실패합니다. 따라서 아래와 같이 생애주기를 분리했습니다.
  • 대기 · 미리보기 중: _orientation_locked = False → 폰을 세우거나 눕히면 즉시 자동 회전.
  • 측정 시작 (init_live_session()): camera.set_orientation_lock(True) → 시작 시점의 가로/세로 방향 고정.
  • 측정 종료 (stop_camera()): camera.set_orientation_lock(False) → 카메라 연결은 유지한 채 자동 회전 즉시 복귀.

4.3 세로 영상 해상도 보존 (compute_downscaled_size)

720p 프리셋(max_width=1280, max_height=720)을 세로 영상(720×1280)에 그대로 적용하면 406×720으로 과도하게 축소되는 문제가 있었습니다. 이를 막기 위해 height > width이고 max_width > max_height인 경우 상한을 (720, 1280)으로 자동 스왑해 세로 720p 화질을 그대로 유지합니다.

5. GoPro USB & DirectShow / IP 스트림

5.1 GoPro 전용 FFmpegDShowCapture

  • 타임아웃 우회: GoPro Webcam 가상 카메라는 대기 로고에서 실영상으로 전환될 때 OpenCV CAP_DSHOW가 1초 타임아웃으로 1 FPS 검은 화면에 갇히는 문제가 있어, FFmpeg subprocess 파이프로 직접 수신합니다.
  • 풀화각 유지: GoPro DirectShow에 1280×720을 요청하면 1080p 중앙을 크롭하므로, 항상 1920×1080(bgr0) 풀화각으로 받은 뒤 FFmpeg 내부 -vf scale로 목표 해상도로 축소합니다.
  • 정상 종료: COM 필터 꼬임을 막기 위해 release() 시 stdin으로 q\n을 전송해 정상 종료합니다.

5.2 프록시 우회 (configure_local_and_gopro_no_proxy)

병원/사내 HTTP 프록시 환경에서 로컬 WebSocket(127.0.0.1)과 GoPro USB 이더넷(172.20~29.x.51) 통신이 차단되지 않도록 모듈 로드 시 NO_PROXY에 로컬 및 172.16.0.0/12 대역을 자동 추가하고, OPENCV_FFMPEG_CAPTURE_OPTIONS="overrun_nonfatal;1|fifo_size;50000000"를 설정합니다.

6. 미리보기 인코딩 & 동적 OpenCV 창 크기

6.1 서버 측 미리보기 인코딩 (encode_preview)

  • PREVIEW_SIZE = (640, 360), PREVIEW_FPS = 25, PREVIEW_JPEG_QUALITY = 55.
  • 세로 프레임(height > width)이면 타겟 크기를 (360, 640)으로 스왑해 리사이즈한 뒤 render_overlay()로 23관절 스켈레톤과 우측 정보 패널을 합성합니다.
  • 최종 JPEG 크기: 가로 기준 약 813×360, 세로 기준 약 457×640 (우측 정보 패널 포함).

6.2 클라이언트 OpenCV 창 자동 리사이즈 (VideoWindow._display)

streamlit_client/client/video_window.py는 수신 프레임의 orientation(portrait vs landscape)이 바뀔 때마다 실제 이미지 비율(img_w / img_h)에 맞춰 cv2.resizeWindow()를 자동 호출합니다. 

if orientation == "portrait":
    win_h = 860
    win_w = max(320, round(win_h * img_w / max(1, img_h)))   # 약 614 x 860
else:
    win_w = 1120
    win_h = max(360, round(win_w * img_h / max(1, img_w)))   # 약 1120 x 496
cv2.resizeWindow(title, win_w, win_h)

8. 설치 · 바이너리 자동 탐색 · 실행

8.1 바이너리 탐색 경로 (새 터미널 없이 즉시 인식)

winget 설치 직후 현재 셸의 PATH가 아직 갱신되지 않았더라도 camera.py가 아래 경로를 순서대로 자동 탐색합니다.

  • FFmpeg (_find_ffmpeg_exe): PATH → socket_server/configs/bin/ffmpeg* → %LOCALAPPDATA%\Microsoft\WinGet\Links\ffmpeg.exe → %LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg*\**\ffmpeg.exe
  • scrcpy (_find_scrcpy_exe): PATH → WinGet\Links\scrcpy.exe → socket_server/configs/bin/scrcpy.exe → tmp/scrcpy/scrcpy.exe → WinGet\Packages\Genymobile.scrcpy*\**\scrcpy.exe
  • adb / scrcpy-server: 탐색된 scrcpy.exe와 같은 폴더에서 adb.exe 및 scrcpy-server를 자동 참조합니다.

9. 자주 발생하는 오류 해결

증상 / 오류 메시지 원인 및 해결 방법
device unauthorized 또는 진단에 승인 대기 중 표시 스마트폰 화면 잠금을 해제하고 "USB 디버깅을 허용하시겠습니까?" 팝업에서 항상 허용을 선택하세요.
scrcpy 또는 ffmpeg를 찾을 수 없습니다 .\socket_server\setup.bat를 실행하거나 PowerShell에서 winget install Genymobile.scrcpy, winget install Gyan.FFmpeg를 설치하세요.
