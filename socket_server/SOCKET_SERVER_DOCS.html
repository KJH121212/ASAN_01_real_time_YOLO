ASAN Motion Socket Server 명세서

YOLOv8n + RTMPose-M (COCO-23: 몸통 17 + 발 6 = 23개 관절) 순수 ONNX Runtime 엔진을 탑재한 실시간 재활 운동 측정 WebSocket 서버의 모든 입력(명령·카메라·영상)과 출력(실시간 패킷·파일)을 정리한 문서입니다.

Endpoint ws://127.0.0.1:8080 Protocol WebSocket JSON (UTF-8) AI Engine Pure ONNX Runtime (~176 FPS) Keypoints 23 (Body 17 + Foot 6) Max Frame 16 MB

1. 아키텍처 & 서버 동작 요약

⚡ 순수 ONNX 추론 파이프라인

PyTorch·MMCV·MMPose 없이 yolov8n.onnx(11.6MB) + rtmpose_coco23.onnx(52.7MB)로 동작합니다. 서버 기동 즉시 소켓이 열리며, 모델은 백그라운드에서 로드됩니다.

🎥 카메라 Keep-Alive

한 번 열린 카메라(GoPro/웹캠/IP Cam)는 CMD_DISCONNECT_CAMERA를 호출하거나 카메라 설정을 바꾸기 전까지 계속 연결 상태를 유지해 다음 측정 시작 시 재연결 지연이 0초입니다.

📦 3가지 실행 모드

LIGHTWEIGHT(수치+관절 JSON), VISUAL(JSON + 25 FPS JPEG 미리보기), OFFLINE_VIDEO(MP4 파일 배치 23관절 분석)를 단일 WebSocket으로 지원합니다.

카메라 / MP4 입력
→
YOLOv8n ONNX (10프레임 주기)
→
RTMPose-M ONNX (23관절)
→
One Euro 필터 + 등방성 정규화
→
FSM 카운트 · 품질 판정
→
WebSocket JSON + CSV/NPZ/MP4

2. 지원 입력 소스 (카메라 · 모바일 · 영상 파일)

입력 종류 지정 파라미터 동작 방식 및 특징
GoPro Webcam (USB) camera_index (정수, 예: 2)
camera_max_width / height		 USB 이더넷(172.2X.X.51)을 자동 탐색해 광각(fov=0)으로 전환하고, ffmpeg DirectShow 파이프로 1080p 풀화각 수신 후 지정 해상도(기본 1280×720)로 축소합니다.
일반 USB 웹캠 / 가상 캠 camera_index (0, 1, 2…)
camera_url 비움		 Windows DirectShow(FFmpegDShowCapture 또는 OpenCV CAP_DSHOW)로 캡처합니다. 안드로이드 USB(scrcpy + OBS 가상 카메라 등)도 동일하게 인덱스로 연결됩니다.
모바일 IP 카메라 / RTSP camera_url (문자열)
예: http://192.168.0.15:8080/video		 camera_url이 비어 있지 않으면 camera_index보다 우선 적용됩니다. HTTP MJPEG, RTSP, SRT 스트림을 OpenCV FFmpeg 백엔드로 수신합니다.
오프라인 영상 파일 (MP4) video_path 또는 input_source
output_mode: "OFFLINE_VIDEO"		 서버 PC 경로의 영상 파일을 batch_size(기본 16) 단위로 ONNX 배치 추론하여 23관절 NPZ·CSV·요약 JSON을 고속 추출합니다.

3. 표준 통신 흐름 (Sequence)

  1. 서버 준비 확인: 클라이언트 → CMD_GET_SERVER_STATUS → 서버 SERVER_STATUS (ready: true 확인)
  2. (선택) 카메라 진단: 클라이언트 → CMD_SCAN_CAMERAS → 서버 CAMERA_SCAN_RESULT
  3. (선택) 독립 미리보기: 별도 소켓으로 CMD_WATCH_CAMERA 전송 → 서버가 25 FPS로 VIDEO_FRAME 스트리밍
  4. 캘리브레이션 (3회 반복): CMD_SET_SESSION (mode: "CALIBRATION") → SESSION_LOG_STARTED → SESSION_PREPARING(관절 인식 후 3초 카운트다운) → SESSION_MEASUREMENT_STARTED → 매 프레임 POSE_UPDATE → 3회 완료 시 CALIBRATION_FINISHED (개인 임계값 저장)
  5. 본 측정 (MAIN): CMD_SET_SESSION (mode: "MAIN") → 매 프레임 POSE_UPDATE + 1회 완료마다 REP_COMPLETED → 목표 도달 또는 CMD_STOP_SESSION 시 SESSION_FINISHED (CSV/NPZ/MP4/요약 저장)
  6. 카메라 연결 유지 / 해제: 측정 종료 후에도 카메라는 계속 연결 유지(다음 운동 즉시 시작). 작업 완료 후 CMD_DISCONNECT_CAMERA로 명시적 해제.

4. 입력 명령 명세 (Client → Server)

모든 요청은 JSON 객체이며 "type" 필드로 명령을 구분합니다.

IN CMD_GET_SERVER_STATUS
응답: SERVER_STATUS

ONNX 모델 백그라운드 로딩 상태(IMPORTING → DEVICE_SETUP → LOADING_YOLO → LOADING_POSE → READY / FAILED)와 소요 시간을 조회합니다.

{ "type": "CMD_GET_SERVER_STATUS" }
IN CMD_SCAN_CAMERAS
응답: CAMERA_SCAN_RESULT

서버 PC에 연결된 DirectShow/웹캠 목록, 해상도, GoPro USB 이더넷 IP(172.2X.X.51)를 진단합니다.

{
  "type": "CMD_SCAN_CAMERAS",
  "max_index": 4
}
IN CMD_DISCONNECT_CAMERA
응답: CAMERA_DISCONNECTED

서버에 Keep-Alive로 유지 중인 카메라(GoPro/웹캠/IP Cam) 연결을 명시적으로 해제합니다. 다른 앱에서 카메라를 쓰거나 GoPro 발열을 줄일 때 호출합니다.

{ "type": "CMD_DISCONNECT_CAMERA" }
IN CMD_WATCH_CAMERA
응답: VIDEO_FRAME (연속) / PREVIEW_STATUS

측정 세션과 독립된 별도 WebSocket 연결로 카메라 영상 및 실시간 23관절 스켈레톤 오버레이 미리보기를 25 FPS로 수신합니다.

{
  "type": "CMD_WATCH_CAMERA",
  "camera_index": 2,
  "camera_url": "",
  "camera_max_width": 1280,
  "camera_max_height": 720,
  "exercise_name": "slr"
}
IN CMD_SET_SESSION
응답: SESSION_LOG_STARTED → POSE_UPDATE / VIDEO_PROGRESS → *_FINISHED

실시간 측정(CALIBRATION / MAIN) 또는 오프라인 영상 배치 분석(OFFLINE_VIDEO) 세션을 시작하는 핵심 명령입니다.

IN 세션 제어 명령 3종
응답: SESSION_FINISHED / CALIBRATION_FINISHED
명령 (type)선택 파라미터동작
CMD_STOP_SESSION reason, session_id, request_id 진행 중인 실시간 측정 또는 오프라인 영상 배치 분석을 정상 중단하고 CSV/NPZ/MP4를 저장한 뒤 SESSION_FINISHED를 반환합니다.
CMD_RESET_SESSION request_id 현재 세션 상태를 강제 초기화(이전 연결 정리 포함)하고 새 세션을 받을 수 있는 상태로 복구합니다.
CMD_STOP_CALIBRATION 없음 CALIBRATION 진행 중 3회 완료 전이라도 현재까지 수집된 데이터로 즉시 캘리브레이션을 마무리합니다.

    "left": { "start_val": -0.85, "target_val": 0.15 },

5. 출력 패킷 명세 (Server → Client)

OUT 상태 · 카메라 · 세션 수명주기 패킷
패킷 type발생 시점주요 출력 필드
SERVER_STATUS 접속 직후 / CMD_GET_SERVER_STATUS model_state (LOADING/READY/FAILED), phase, ready, message, elapsed_seconds, phase_seconds

6. 서버 파일 출력물 (data/ 저장 구조)

세션이 종료되면 서버 PC의 data/(또는 요청의 log_root) 아래 환자·날짜·운동별 폴더에 아래 파일이 자동 저장됩니다.

NPZ 23관절 시계열 데이터 (*.npz)

프레임별 timestamps, keypoints (N × 23 × 3: x, y, score), 원본 프레임 번호(video_frame_idx)를 압축 저장하여 오프라인 스켈레톤 재생 및 재시뮬레이션에 사용됩니다.

CSV 프레임별 측정 신호 로그 (*.csv)
